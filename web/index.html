Как пользоваться тестами и чеклистами

• Выберите сюты чекбоксами («в батч») и запустите кнопкой «Запустить выбранное» — или запускайте каждый сьют индивидуально из его карточки.

• Во время прогона на карточке отображается прогресс; после завершения выводится итоговый статус и кнопки «Отчёт» и «Логи».

• Кнопка «Все логи» в шапке открывает глобальный журнал событий из любого раздела с фильтрами, поиском и экспортом.

• Клик по строке в табе «История» открывает отчёт: таймлайн шагов и технические сетевые детали.

• Пользовательские сценарии создавайте в табе «Редактор сценариев» — они автоматически появятся в каталоге.

Шпаргалка
  • Подстановка в строках (path, body, left): {{var}} — vars сценария или результат extract; спецпеременные {{uuid}} и {{today}}.
  • extract: имя переменной → JSONPath ответа, например $.data.order_id. Далее используйте как {{order_id}}.
  • expectStatus: точный код (200, 404…) или класс («2xx», «4xx», «5xx»). Пусто — статус не проверяется.
  • asserts HTTP-шага: JSONPath ($.x) + оператор eq / neq / contains / exists (value не нужен для exists).
  • Шаг assert: сравнение значения/переменной ({{var}}): notEmpty / eq / neq / contains.
  • Роль (role): чей Bearer-токен отправить; none — без авторизации.

Аккаунты для прогонов

По умолчанию каждый прогон создаёт новые аккаунты — так тесты не мешают друг другу. Выберите профиль, чтобы сьюты шли под конкретным аккаунтом: это нужно, когда на стенде есть подготовленные вручную данные, которых у сгенерированной фикстуры не будет.

Привязка хранится вместе с токенами стенда и переживает перезапуск. У привязанного ресторана сьют заказывает существующее блюдо и выставляет круглосуточное расписание, чтобы точка была открыта.
